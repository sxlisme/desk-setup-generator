# 桌搭清单生成器

个人使用的桌搭清单工作台，支持设备库、4:3 设备图片、模板管理、图片资产、完整备份恢复和单管理员登录。整张清单导出为 3:4、3072 × 4096 像素的 PNG。

## 首次配置登录

需要 Node.js 22 或更新版本。复制示例配置：

```bash
cp .env.example .env
```

编辑 `.env`，填写自己的账号和密码：

```dotenv
ADMIN_USERNAME=admin
ADMIN_PASSWORD=请替换为至少12位且不重复使用的密码
COOKIE_SECURE=false
PORT=3000
```

示例中的密码文字只用于说明，务必改成自己的密码。没有设置密码或不足 12 位时，服务会拒绝启动。`.env` 不会提交到 Git，也不会进入 Docker 构建上下文。服务启动后在内存中使用 scrypt 派生值校验密码，备份不包含账号密码。请限制服务器上 `.env` 的读取权限。

适配 HTTP：保持 `COOKIE_SECURE=false`。会话采用 HttpOnly、SameSite=Strict Cookie，7 天过期，退出或服务重启后失效；接口和上传图片都要求登录，写入操作校验 CSRF，会限制失败的登录尝试。HTTP 本身不加密密码或会话传输，这些保护不能替代 HTTPS；不要复用其他网站的密码。

以后启用 HTTPS 时，将 `COOKIE_SECURE=true`。使用反向代理时应保留原始 Host；也可配置 `PUBLIC_ORIGIN=http://你的域名:端口`，值须与浏览器访问的完整来源一致（HTTPS 时使用 https）。忘记密码可修改服务器 `.env`，然后重启服务。

## 本地开发

```bash
npm ci
npm run dev
```

- 前端：http://localhost:3001
- API：http://localhost:3000

开发时请通过前端地址访问，Vite 会代理 API 和上传图片。前后端使用同源 Cookie。

## 生产运行

```bash
npm ci
npm run build
npm start
```

访问 `http://服务器地址:3000`。只需开放服务端口，内置 Express 会提供构建后的页面、API 和图片。

## Docker 部署

先填写项目目录的 `.env`，然后：

```bash
docker compose up -d --build
```

`data` 目录通过 volume 持久化，包含数据库、上传图片和恢复前快照。调整登录配置后执行 `docker compose up -d --force-recreate`。更新代码后重新构建。

## 模板管理

- **另存为**：创建独立模板并切换到新模板；同名也有独立编号。
- **保存修改**：载入模板后更新当前模板，保持编号不变。
- **模板库**：按名称或编号搜索，支持重命名、载入和确认删除。重命名保留模板内容。
- 当前正在编辑的模板显示在预览上方。草稿自动保存到服务端，备份也会包含草稿；页面底部显示保存状态。更新前的浏览器草稿会在服务器尚无草稿时尝试迁移。

## 设备图片

设备图区域为 4:3，建议 800 × 600 像素的透明背景 PNG，单张不超过 12 MB。支持 PNG、JPG、WebP、GIF、AVIF，上传时检查文件标识。不同长宽比等比完整显示、不裁切，清单卡片为类型标签留有底部空间。

新增或编辑设备时，可直接按 `⌘V` / `Ctrl+V` 粘贴截图或图片，上传后保存。主图也支持粘贴：先聚焦“更换照片”按钮（可用 Tab），再粘贴。普通文本粘贴不受影响；复制图片网址不会自动上传。

## 类型管理

在设备库或设备编辑窗口输入名称即可新增类型（1–16 个字符）。“数据管理 → 类型管理”支持：

- 上移、下移排序，保存后重启仍保持顺序。
- 重命名，同步更新设备库、模板内的设备和当前草稿。
- 合并到已有类型，统一修改引用并移除原类型。
- 删除空类型。仍被设备、模板或草稿引用时拒绝删除，可以先合并。

筛选区多行排列，超出高度后可以用滚轮、触控板或滚动条上下浏览。

## 图片资产

“数据管理 → 图片资产”展示已上传图片、文件名、大小和引用来源，支持文件名搜索、放大预览、仅看未使用及确认删除。引用检查包含设备库、所有模板和当前服务端草稿。正在使用的图片不能删除；先移除引用后再删除。打开管理窗口前会先保存当前草稿。

## 完整备份与恢复

“数据管理 → 备份恢复”下载 `.deskbackup.gz` 压缩包，包含设备、类型顺序、模板、当前草稿和全部上传图片，不含账号密码与历史恢复快照。支持上传图片总量不超过 150 MB，单图不超过 12 MB；备份上传最大 160 MB。

恢复流程：选择文件 → 校验并预览条目数量 → 确认覆盖恢复。校验失败不会修改现有数据，恢复会替换当前设备、类型、模板、草稿和图片；替换过程失败会尝试回滚。恢复前自动写入 `data/backups/before-restore-*.deskbackup.gz`，可在同一页面下载，再作为普通备份恢复。

恢复后其他已打开的页面应刷新；旧草稿提交会被拒绝，防止覆盖恢复结果。自动快照会占用磁盘，可在确认不再需要时通过服务器文件管理清理。完整备份包含私人图片，请妥善保管。
